Apple quietly ships an official Xcode plugin for Claude Code — no announcement, just a merged PR

Apple is now listed as the author of an official Xcode plugin in Claude Code's marketplace, giving the agent build, test, preview, and simulator control — and the company hasn't said a word about it.

MDMarcus DoyleSenior Technology Writer · November 8, 2026 · 6 min read
TL;DR: Apple is now the listed author of an official Xcode plugin in Claude Code's marketplace. It exposes Xcode to the agent over MCP: builds, tests, SwiftUI previews, simulators, build logs, and Apple docs search. The pull request adding it was merged on November 6, Apple has said nothing about it publicly, and the listing was spotted on X the next day.

Apple now ships an official Xcode plugin for Claude Code — and nobody at Apple announced it. The plugin quietly appeared in Anthropic's official plugin marketplace this week, listed with Apple Inc. as its author, giving Claude Code the ability to build, run, and test Xcode projects, render SwiftUI previews, drive simulators and devices, and read build logs. The listing was spotted on X on November 7, a day after the pull request that added it was merged.

It is a small listing with a large implication: the company that guards the iOS and macOS toolchain most jealously is now officially building for a rival lab's coding agent — and doing it so quietly that the community found out from a merged pull request, not a press release.

What the plugin actually does#

The marketplace entry describes the plugin plainly: work with Xcode projects from Claude Code — build, run, and test schemes, render SwiftUI previews, drive simulators and devices, read build logs and diagnostics, and search Apple developer documentation. In practice that means an agent working in a terminal can compile a project, run its tests, see a SwiftUI preview, and read the build errors without a developer shuttling output between Xcode and the chat window.

The delivery mechanism is the telling detail. The marketplace entry does not point at a GitHub repository to download. Its source is a command — xcrun agent plugin path --plugin-format claude — which resolves the plugin from the Xcode install already on the machine. Apple is distributing the plugin through Xcode itself, and the marketplace listing is effectively a pointer to it. That also means it requires a Mac with a current Xcode: this is not a plugin you can run on a Linux box.

How it surfaced#

The paper trail is short. Pull request #6338, titled “Add Xcode plugin (xcode),” was opened in Anthropic's claude-plugins-official repository on September 30 and merged on November 6 at 00:55 UTC. It carries over an earlier change from pull request #6259, and its only file change is a single entry in the marketplace manifest — the plugin itself lives in Xcode, not in the repository. A day later, an X post flagged the new listing, and the news spread from there.

Apple has issued no statement, no developer blog post, and no press note about the plugin that we could find. That silence fits a pattern: Apple documents the underlying machinery — its developer site has a page on giving external agents access to Xcode — without making a fuss about any single agent integration. The company is building the plumbing and letting the ecosystem notice.

Why it matters#

Two things make this more than a marketplace footnote. First, the direction of travel. In February, Xcode 26.3 brought Claude Agent and OpenAI's Codex inside the IDE itself, letting developers delegate whole tasks from within Xcode. Now Apple has gone the other way too, putting Xcode's capabilities inside Claude Code. The two products are meeting in the middle, and the developer gets to choose which side of the integration they work from.

Second, the author line. Anthropic's official marketplace already lists plugins from identity and security vendors — Auth0, WorkOS, Vanta, CrowdStrike-adjacent tooling — but a platform owner shipping an official plugin for a third-party agent is a different signal. Xcode is the gatekeeper for shipping on Apple platforms; an official plugin means Apple is willing to let an outside agent drive that gatekeeper, on Apple's own terms, through its own tooling.

What to watch#

The obvious question is whether Apple says anything at all. A quiet listing could stay quiet, or it could be the prelude to a documented, supported integration with release notes and a WWDC-style showcase. Watch Apple's developer documentation for the plugin: if it gains its own page, samples, or a mention in Xcode release notes, the integration is being treated as a real product rather than plumbing.

The second question is capability. Today the plugin covers the core loop — build, test, preview, simulate, read logs. The interesting additions would be deeper ones: Interface Builder and asset catalog work, App Store Connect actions, or TestFlight flows, all of which would move the agent from coding assistant toward release assistant. And the third question is whether other platform owners follow: Google has its own agent story for Android Studio, and Microsoft owns both the editor and the model in the Copilot world. Apple just showed that a platform owner can bless a rival's agent without giving up control of the toolchain — and that may be the part everyone else copies.
