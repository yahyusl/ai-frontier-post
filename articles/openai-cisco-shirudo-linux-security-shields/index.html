OpenAI and Cisco launch Shirudo: AI-written shields that guard Linux while patches catch up

OpenAI and Cisco have launched Shirudo, an open-source Linux runtime that lets AI agents write temporary eBPF shields to block exploits on running systems — no restart, no waiting for the patch.

MDMarcus DoyleSenior Technology Writer · November 24, 2026 · 6 min read
TL;DR: OpenAI and Cisco have launched Shirudo, an open-source Linux runtime that lets AI agents write temporary eBPF shields to block exploits on running systems while the real patch is prepared — no restart required. Built on Cisco’s Tetragon platform, it was demonstrated blocking a Java4Shell attack on a live Elasticsearch service. It is pre-release, Linux-only, and every shield still needs a human’s approval.
  • The launch: OpenAI and Cisco launched Shirudo on November 23, 2026 — Japanese for “shield” — an open-source Linux runtime (BSD-licensed) that lets AI agents write temporary exploit shields.
  • How it works: agents trace a vulnerability to the affected code paths, write a small eBPF shield or application bytecode, test it against a live exploit reproducer, and hand it to a human operator for approval.
  • The proof point: in a controlled test, a shield generated by OpenAI’s Codex blocked a Java4Shell exploit against a running Elasticsearch service without interrupting it; a recent PHP flaw was also blocked in testing.
  • The guardrails: shields are cryptographically signed, distributed as “.bee” packages via an OCI registry, and verified with the host’s TPM before loading; each shield retires when the real patch lands.
  • The limits: pre-release, Linux-only, and production use currently needs a patched kernel plus TPM 2.0 hardware — and skeptics warn an AI-written kernel rule can break a service as surely as an exploit.

A critical flaw in a widely used library can now be found — and weaponized — by AI faster than defenders can patch it. Getting the fix onto every affected machine still takes days or weeks of testing, scheduling, and restarts. OpenAI and Cisco want to close that gap with something in between: a temporary shield, written by an AI agent, that blocks the exploit on a running system while the real patch makes its way through.

The tool is called Shirudo — Japanese for “shield” — launched as an open-source project on November 23. It targets the window defenders dread most: the period after a vulnerability is public and before a patch is safely deployed.

What Shirudo actually does#

Shirudo is a Linux runtime built on eBPF, the kernel technology that lets small, sandboxed programs attach to hooks inside the operating system without modifying kernel source code or rebooting the machine. When a new vulnerability surfaces, an AI agent — OpenAI demonstrated the workflow with Codex — reads the disclosure and the affected code, traces the flaw to the assets and attack paths it touches, and writes a small, targeted shield: eBPF code in the kernel, or application bytecode higher up the stack.

The shield is tested before anyone trusts it. The agent reproduces the exploit, checks that the shield stops it, and checks that the service still runs normally. Operators can watch a proposed shield against real traffic before flipping it into enforcement mode. Only when the evidence says it is safe does the shield graduate to active blocking — and it retires the moment the real patch lands.

Distribution is designed to be trustworthy rather than merely fast. Shields travel as cryptographically signed “.bee” packages through an OCI-compliant registry, and the Shirudo layer on each target machine validates the signature using the host’s Trusted Platform Module before loading anything. The design rests on four pillars: live protection, AI-assisted defense, trusted deployment via signatures and the eBPF verifier, and hardware-backed verification of every shield loaded or removed.

A Tetragon rewrite, built for agents#

Shirudo did not appear from nowhere. It is a rewrite of Tetragon, the open-source eBPF runtime security platform that Isovalent — acquired by Cisco in 2024 — released in 2022, and which already powers Cisco’s commercial Live Protect feature. The difference is the audience: where Tetragon was built for human operators and policy languages, Shirudo is designed for an agentic control plane, with a configurable degree of autonomy over deploying mitigations.

That choice is deliberate. Isovalent’s engineers argue that pointing agents at human-friendly dashboards bottlenecks them; Shirudo instead exposes programmable OS controls directly, so an agent can write a mitigation in code, test it against a live exploit, and hand a human operator a finished shield to approve. The companies describe the project as a first step toward “self-defending infrastructure.”

The demo: Java4Shell stopped on a live service#

The launch came with a concrete test rather than just a diagram. In a controlled experiment, a shield generated by OpenAI’s Codex blocked a Java4Shell exploit attempt — a remote-code-execution flaw in OpenJDK — against a running Elasticsearch service, without interrupting the service or restarting anything. Reporting on the launch also notes the system blocked a recent PHP flaw in testing.

The companies say they will ship “ready-to-use” shields alongside vulnerability disclosures until patching is possible, so teams that cannot write their own mitigations still get coverage. Deployed shields also report hit counts, showing where exploit attempts are landing. OpenAI plans a technical deep dive in a webinar on December 15.

The limits — and the skepticism#

For all the ambition, Shirudo arrives with clear limits. The project is pre-release, and production use currently requires a patched kernel plus TPM 2.0 hardware. It is Linux-only: macOS and Windows lack the kernel components the approach depends on. And the shields are temporary by design — a stopgap, not a substitute for patching.

The skepticism is substantive. Marcus Hutchins, principal threat researcher at Expel, told BleepingComputer there is “genuinely so much runtime exploit mitigation potential with eBPF,” while questioning whether AI agents should be writing rules that can affect the kernel. The concern is practical: an over-broad or mistaken shield can break a service just as surely as an exploit can, which is why the human approval step matters more than the demo suggests.

What to watch#

Shirudo lands at a moment when the offense-defense balance is visibly tilting. Cisco’s Thomas Graf and Isovalent’s Liz Rice put it bluntly: AI models have become remarkably good at finding and exploiting software vulnerabilities, and exploitation can now begin before a fix even exists. Shirudo is the defense side’s answer to that math: fight machine-speed attacks with machine-speed shields.

Three things will decide whether it works: how quickly the ready-to-use shield library grows beyond the launch demos; whether operators trust AI-written kernel controls enough to deploy them, even with a human in the loop; and whether the project stays genuinely open — it is BSD-licensed, its BPF programs dual-licensed under BSD and GPL — or drifts toward a paid Cisco offering, as some commentators already suspect. For now, Shirudo is a credible, narrowly scoped idea: not a replacement for patching, but a shield to hold the line while the patch is on its way.

Frequently asked questions

What is Shirudo?

Shirudo is an open-source Linux runtime from OpenAI and Cisco that lets AI agents write temporary security shields. When a vulnerability is disclosed, an agent traces it to the affected code, writes a small eBPF shield that blocks the vulnerable path, tests it against a live exploit, and hands it to a human operator for approval — all without restarting the service.

Does Shirudo replace patching?

No. Shields are temporary by design: they block exploitation while a permanent patch is tested and rolled out, then retire once the patch lands. The project is explicitly a stopgap for the window between disclosure and deployment, not a substitute for fixing the underlying flaw.

Can I use Shirudo in production today?

Not yet in the usual sense. The project is pre-release, Linux-only, and production use currently requires a patched Linux kernel plus TPM 2.0 hardware. OpenAI plans a technical deep dive in a webinar on December 15, 2026, and the companies say ready-to-use shields will ship alongside vulnerability disclosures.
