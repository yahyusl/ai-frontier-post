Claude wrote a transformer’s weights by hand — no training — and it solves every maze

Researchers at MBZUAI asked Claude Opus 5.5 to write every weight of a small transformer by hand, with no training at all. The result solves 100% of hard 30×30 mazes — a task the model itself only manages 26% of the time.

PNPriya NairResearch Editor · November 24, 2026 · 8 min read
TL;DR: Claude Opus 5.5 wrote every weight of a 19,936-weight transformer by hand, with no training — and it solves 100% of hard 30×30 mazes, where Claude answering in text manages 26%. The trick is a loop: one block runs over and over, each pass advancing a shortest-path search one step. It took 39 minutes and about $19, beating every trained model on the benchmark, and the same approach scored 100% on Sudoku, the Tower of Hanoi and million-token graph walks.
  • The result: a single-block transformer with 19,936 weights, written entirely by Claude Opus 5.5 in a Claude Code session, solves 100% of the Maze-Hard test mazes. Claude answering the same mazes in text solves 26%.
  • The cost: 39 minutes and about $19 in Claude API tokens. The best trained model, EBR, uses 1.8 million weights and 1,160 PFLOPs of training compute and reaches 93.5% in the team’s runs.
  • The loop: one block runs over and over; each pass moves a shortest-path search one step further, so a bigger maze needs more passes, not more weights. The same weights solved every one of 50 mazes at 60×60 and 40 at 100×100, though Claude only checked them up to 45×45.
  • Beyond mazes: Sudoku-Extreme (all 141,040 test puzzles), the 20-disk Tower of Hanoi (1,048,575 moves, zero mistakes) and million-token GraphWalks prompts (100%, against 66.8% for Claude itself).
  • The catch: it only works when the algorithm is already known — the model is writing down a search, not discovering one. A blog post, not a peer-reviewed paper; the code and weights are public for anyone to check.

Ask Claude Opus 5.5 to solve a hard maze and it will fail most of the time. Ask it to build a machine that solves mazes, and it writes every weight of that machine by hand — and the machine gets every maze right. That is the result researchers at MBZUAI published on Monday, November 23: a transformer with 19,936 weights, set by Claude in a Claude Code session, with no gradient training anywhere in the process. On Maze-Hard, a benchmark of 30×30 mazes whose shortest paths run longer than 110 steps, it solves 100% of the test mazes. Claude answering the same mazes in text solves 26%.

The work is called looped weight-space programming, and it arrived as a blog post, not a paper — with the weights, code and prompts all released under the MIT license. It took 39 minutes and about $19 of Claude API tokens. The same weights also solve larger mazes they were never checked on — every one of 50 mazes at 60×60 and 40 at 100×100. It is a striking demonstration, and a narrow one: the trick only works when you already know the algorithm you want the network to run.

What Claude actually built#

The transformer is almost comically small by 2026 standards: a single block, 19,936 weights, no training. Claude made each cell of the maze one token, so a 30×30 maze becomes 900 tokens, and gave every cell a memory of 35 numbers, each with a meaning Claude decided before setting a single weight. Some record what the cell is and where it sits; others track the search: distance from the goal, next step, and whether it lies on the path.

The block has four attention heads, one per direction. Each loop, every cell reads its neighbours and updates its numbers. A wave of distances spreads outward from the goal, one cell per loop; once it reaches the start cell, a path grows back toward the goal, one cell per loop. On the first test maze, the wave arrives at loop 111 and the path is complete at loop 222. Because every number has an assigned meaning, the computation is readable: you can watch the search spread, loop by loop. Remove any one attention head and the wave reaches only about 8% of the cells it should, and no mazes get solved. A version capped at 1,000 weights still scored 100% — the smallest used 928.

Why the loop is the trick#

Writing weights by hand is not new. Compilers like Tracr already turn short programs into transformer weights, and MIT CSAIL showed this year that a frontier model can edit weights directly, without training. But earlier LLM-written transformers had a scaling problem: every step of a computation needed its own block, so a harder problem meant a far bigger transformer — and a far bigger bill, since the model has to write every one of those extra weights.

The loop fixes that. One block does one step of the search, and the transformer runs that block again and again, for as many steps as the problem needs. A bigger maze needs more passes, not more weights. That is why the same 19,936 weights handle a 100×100 maze, and why the approach stretches to problems with chains of reasoning thousands of steps long.

And the last row is the one the authors linger on: when they reset Claude’s transformer to random weights and trained the same architecture on the same 1,000 training mazes, every run solved 0% of the test mazes. Gradient descent, in their runs, never finds these weights at all.

Beyond mazes#

Mazes are the headline, but the team ran the same recipe on nine tasks, and the written transformer scored 100% on every one. On Sudoku-Extreme it solved all 141,040 test puzzles. On the Tower of Hanoi, a 3,686-weight block looped more than two million times to play all 1,048,575 moves of the 20-disk puzzle without a single mistake — where Claude 3.7 Sonnet and DeepSeek-R1 drop to zero by 11 disks. On GraphWalks, million-token prompts scored 100%, against 66.8% for Claude itself. Several BIG-Bench tasks came out at 100% too, where the best models the team could find scored between 33% and 81%. Claude wrote all of them in 18 sessions, each costing between about $1 and $37 at list prices.

The pattern is consistent: wherever the task is a long chain of exact steps, the model that writes one step into weights and loops it beats the model that tries to carry the whole chain in its head. The team tried hard to get Claude to solve mazes directly, and the best prompt got it from 26% to 50%, and no higher. Writing the transformer is a different kind of task: Claude does not have to run the search, only design one step and set weights to match.

What it doesn’t mean#

The limits matter as much as the scores. This only works when you already know the algorithm. Claude is writing down a shortest-path search humans worked out decades ago, in a form a transformer can execute. Nothing here is a path to a general model, and the authors do not claim otherwise.

There are also the usual caveats. This is a blog post, not a peer-reviewed paper, and no independent group has reproduced the results yet. The test set was run once, at the end, and everything needed to check the work is public. One fairness note the authors make themselves: each of their from-scratch training runs used about 5 PFLOPs, far less compute than the trained models they compare against, so the result shows gradient descent did not find these weights under the settings tested — not that the weights cannot be learned.

What to watch#

First, reproduction: whether other groups run the public weights and get the same 100%, and whether the approach holds up on tasks where the algorithm is less cleanly known in advance. Second, the authors’ own next steps: composing these hand-written modules into a single transformer for many tasks, and using written weights as a starting point for training. Third, interpretability: a transformer whose every number means something is a test case for the tools that try to read trained models.

The post spread across Reddit within hours — the numbers are that clean: 19,936 weights, 39 minutes, $19, 100%. Training is not going anywhere. But for one class of problems, the best model in the world right now was not trained at all. It was written.

Frequently asked questions

How can a transformer solve mazes without any training?

Because its weights are set analytically instead of learned. Each of the 35 numbers in a cell's memory is given a meaning up front — what the cell is, its distance from the goal, which way it points — and the weights are chosen so each loop performs one step of a standard shortest-path search. The loop repeats that step until the maze is solved.

Did Claude really write all 19,936 weights itself?

Yes, in a Claude Code session, filling in the weight matrices with code. The team ran the test mazes only once, at the end, and the prompts Claude received are published in the project's GitHub repository, along with the weights. Claude Opus 5.5 is listed as a co-author of the work.

Does this mean training is obsolete?

No. The method only works when you already know the algorithm you want the network to run — here, a shortest-path search. Claude is writing down a search procedure, not discovering one. The authors frame it as a way to study how algorithmic reasoning can live inside neural networks, and as a target for training methods to aim at.

Can I run the maze transformer myself?

Yes. The weights, code and prompts are public on GitHub under the MIT license, and the project page has in-browser demos of the maze and Tower of Hanoi transformers. The run script needs only Python 3 and numpy.
