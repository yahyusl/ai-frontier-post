AWS Bedrock AgentCore Web Search API: InvokeWebSearch gives AI agents web search in one call

AWS made web search a one-line API call for AI agents on Tuesday, announcing general availability of the Web Search API on Amazon Bedrock AgentCore. The new InvokeWebSearch endpoint returns ranked results from Amazon's own web index — no gateway to build, no extra charge beyond $7 per 1,000 queries.

What we checked: AWS What's New announcement “Amazon Bedrock AgentCore now offers a Web Search API,” published November 10, 2026, cross-checked against the Amazon Bedrock AgentCore release notes and Bravelo's November 10 pricing check.

MDMarcus DoyleSenior Technology Writer · November 10, 2026 · 6 min read
TL;DR: AWS announced on November 10, 2026 that the Web Search API on Amazon Bedrock AgentCore is generally available. The new InvokeWebSearch call lets applications, custom agent loops, and data pipelines search the web with the AWS SDKs or the AWS CLI — no AgentCore Gateway to set up — returning ranked results from Amazon's web index at $7 per 1,000 queries.
  • What: general availability of the Web Search API (InvokeWebSearch) on Amazon Bedrock AgentCore.
  • When: announced Tuesday, November 10, 2026, in an AWS What's New post.
  • Price: $7 per 1,000 queries — the same rate as Web Search through AgentCore Gateway, with no gateway charges.
  • Regions: six at launch — US East (N. Virginia), US East (Ohio), US West (Oregon), Asia Pacific (Sydney), Asia Pacific (Tokyo), and Europe (Ireland).
  • What it returns: ranked results from Amazon's web index; each result carries a text extract and, when available, the page title, URL, and publication time.
  • How to call it: AWS SDKs or the AWS CLI, authorized with IAM, callable from a VPC through PrivateLink, and logged as CloudTrail data events.
The verdict: This is the boring, useful kind of launch: AWS took a capability that already existed behind a gateway and turned it into a plain API call at the same price. If your agents already run on AWS, there is no longer a reason to wire up a gateway just for web search — or to pay a third-party search API for the same job.

What changed today#

Web Search on AgentCore is not new. AWS shipped it in June 2026 as a managed tool that agents reached through an AgentCore Gateway, over the Model Context Protocol. It worked, but it came with homework: create a gateway, add a web-search target, wire up the MCP plumbing, and pay the gateway charges on top of the $7 per 1,000 queries.

Tuesday's announcement removes the homework. InvokeWebSearch is a direct API: one call from the AWS SDKs or the AWS CLI, with nothing to provision first. AWS says the API is aimed at "applications, custom agent loops, and data pipelines" — in other words, the code you write yourself, not just agents running inside a framework.

What comes back is the same material the Gateway tool returned. Each result is ranked from Amazon's own web index — tens of billions of documents, refreshed continually, with a knowledge graph behind it, according to AWS's June launch post — and carries a text extract plus, when available, the page title, URL, and publication time. Every request can be filtered by domain and by publication time, so an agent can restrict itself to trusted sources or a recent window. AWS's own examples: finding recent product announcements, or checking a claim against trusted domains.

How it works in an agent loop#

Picture a research agent asked to verify a claim before it answers. It calls InvokeWebSearch with a natural-language query, gets back ranked snippets with their sources and dates, filters the request to a handful of trusted domains and the last 30 days, and grounds its answer in what came back. No scraper to maintain, no third-party search key to manage, no outbound credentials to rotate.

The enterprise controls are the point for AWS's core audience. Calls are authorized with IAM, so the same policies that govern the rest of a team's AWS estate govern search. The API can be called from inside a VPC through PrivateLink, keeping traffic off the public internet, and requests are logged as CloudTrail data events for audit. That is the whole pitch in one sentence: web search that behaves like any other AWS service.

The timing fits a broader Bedrock push. Kimi K3.1 Pro arrived on Bedrock last week, and Google Cloud answered with its own open AI-native stack the same morning. AWS is now filling in the plumbing around the models — the unglamorous pieces that decide whether an agent system is shippable.

What it costs — and the two other ways to buy the same search#

The price is the headline for anyone already paying for search: $7 per 1,000 queries, exactly what the Gateway route costs, minus the gateway. At that rate, a search-heavy agent making 10,000 queries a day spends $70 a day. But AWS now sells the same underlying search three different ways, and the differences matter.

RouteHow you call itPrice per 1,000 queriesThe trade-off
InvokeWebSearch (new)AWS SDK / CLI, direct API call$7Six regions only; extracts, not full pages
Web Search via AgentCore GatewayMCP tools/call on a gateway$7, plus gateway chargesYou build and run a gateway; the MCP-native route
Web Search on BedrockBuilt-in tool in the Responses API$12Only for OpenAI models on Bedrock; not on Converse or InvokeModel

The $12 figure belongs to the built-in Web Search tool AWS added to Bedrock model calls in August, which grounds a model's own response rather than serving a standalone search. The new API is the cheapest way to get Amazon's index into your own code — and the only one that needs no other AWS resource first. That matters in a week when the Open Markets Institute warned that whoever controls agent gateways controls the agent economy: a direct API is one less gate to pass through.

The catch#

Three limits are worth knowing before you build on it. First, geography: six regions at launch, and the list skips Frankfurt, Mumbai, Singapore, and GovCloud, so teams standardized on those regions wait. Second, depth: results are text extracts, not the full page. An agent that needs the whole document — a contract, a paper, a long report — still has to fetch it itself.

Third, it is an index, not the live web. AWS says its index reflects new content within minutes, and the June launch post describes tens of billions of documents refreshed continually. But a curated index is still a snapshot with a refresh lag, and AWS publishes no freshness guarantee for the newest pages. For grounding answers in current events, that is usually fine; for catching something published five minutes ago, verify before you trust it.

AFP take: AWS is quietly turning Bedrock into the one-stop shop for agent plumbing: models, memory, tools, and now search, all behind one IAM boundary. At $7 per 1,000 queries with no gateway to run, the direct API is the obvious default for teams already on AWS — and a reason for everyone else to stop paying a third-party search API for the same job. What to watch: whether the direct API gets the same region coverage and feature treatment as the Gateway tool, or stays a step behind it.

Frequently asked questions

What is the InvokeWebSearch API?

A generally available API on Amazon Bedrock AgentCore, announced November 10, 2026, that lets applications, custom agent loops, and data pipelines search the web with a single call through the AWS SDKs or the AWS CLI — with no AgentCore Gateway or other resource to set up first.

How much does the Web Search API cost?

$7 per 1,000 queries, the same rate as Web Search through AgentCore Gateway, with no gateway charges. It is available in six regions: US East (N. Virginia), US East (Ohio), US West (Oregon), Asia Pacific (Sydney), Asia Pacific (Tokyo), and Europe (Ireland).

How is InvokeWebSearch different from Web Search through AgentCore Gateway?

Both query the same Amazon-operated web index at the same $7 per 1,000 queries. The difference is integration: InvokeWebSearch is a direct SDK or CLI call with IAM authorization, VPC PrivateLink support, and CloudTrail logging, while the Gateway version is an MCP tool that requires building and running a gateway — and paying its charges.
