llama.cpp hits 1.0: the local AI engine finally gets a stable API

After three and a half years of commit-number builds, the engine behind most local AI gets semantic versioning, a pruned public API, and a stable promise to the apps built on it.

MDMarcus DoyleSenior Technology Writer · November 13, 2026 · 6 min read
TL;DR: llama.cpp, the inference engine behind most local AI apps, shipped version 1.0.0 on November 13. It removes the deprecated public API, adopts semantic versioning, and adds FP8 KV caches, new model architectures, and a hardened llama-server — plus Llama desktop apps for macOS and Windows.
  • v1.0.0: llama.cpp and ggml both reach 1.0 on November 13, 2026, after three and a half years of commit-number builds; semantic versioning applies from here on.
  • API: 35 deprecated functions removed; the NextN speculative-decoding API is promoted to llama.h; breaking changes now require a major-version bump.
  • Community: the announcement became r/LocalLLaMA's fastest-moving post of the day; the top response asked for more maintainers, citing unmerged work such as Adaptive KV and Nvidia's Dory model.

The engine that quietly powers most of the local AI world just grew up. llama.cpp — the C/C++ inference library behind Ollama, LM Studio, and a long tail of apps that run models on ordinary hardware — released version 1.0.0 on Thursday, trading three and a half years of commit-number builds for semantic versioning and a promise: the public API is now stable, and breaking changes will arrive with a major-version bump.

The release landed on Thursday morning, announced on Hugging Face's blog and on r/LocalLLaMA by Merve, a Hugging Face engineer on the project, where it quickly became the subreddit's fastest-moving post of the day. The blog post frames v1.0 as a responsibility statement as much as a release: with more downstream apps depending on llama.cpp's library interfaces every year, the team is committing to make API and ABI breaks visible through major-version bumps — and to be stricter about them as adoption grows.

What 1.0 actually changes#

The headline change is a pruning. Version 1.0 removes the deprecated public API — 35 deprecated functions, plus the warmup setter and the defragmentation threshold option — and promotes the NextN speculative-decoding API into the main llama.h header. The message to developers is blunt: if your app was leaning on a deprecated call, it is time to move. The companion tensor library ggml ships as v1.0.0 at the same time, with its own deprecated API and legacy operations pruned.

Just as important is what does not change. The project has used raw commit numbers as version strings since its start in March 2023 — builds like '12360' that told you nothing about compatibility. From here on, llama.cpp follows semantic versioning: major bumps for breaking C API changes, minor for backward-compatible features and new model support, patch for bug fixes.

What's new under the hood#

Beyond the API work, v1.0 is a large feature release. It adds OCP FP8 key-value caches, a host-memory cache for mixture-of-experts models with a configurable CPU share, and loading of external PLE shards from separate GGUF files. Three new text architectures arrive — Kimi-K3.1-Pro, the 65-billion-parameter Ripple preview, and xing4_0 — alongside drama-3 text-to-speech and vision support for MageVL-Cowork and Kimi-K3.1. The project now supports more than 150 architecture variants.

llama-server, the OpenAI-compatible API server many apps talk to, gets a security pass: fixes for server-side request forgery via the CORS proxy, DNS rebinding, and child-instance access, plus an opt-in model for unauthenticated tools. It also gains a /v1/audio/speech endpoint, cancellation of MCP tool calls when a client disconnects, and a redesigned web UI with chat groups and a live-preview markdown editor.

Distribution widens, too. Pre-release artifacts cover Linux, macOS, Windows, Android, and iOS, with Docker, Debian, Homebrew, conda-forge, MacPorts, Winget, and XCFramework channels listed in the release notes.

The desktop apps arrive with it#

The team used the announcement to flag a second product: Llama desktop apps for macOS and Windows, built on llama.cpp and aimed at making local AI a few clicks away rather than a build-from-source exercise. The apps are the project's most direct pitch to non-developers — the same engine, without the terminal.

The community's first reaction#

The announcement thread's most popular response was not a congratulation but a request: more maintainers. Readers pointed to a long backlog of open issues and pull requests, and argued that llama.cpp trails faster forks — naming Strata and unmerged performance work such as Adaptive KV — while Nvidia's Dory model support, proposed in pull request #30306, still waits to be merged. Others pushed back, noting that llama.cpp still runs on legacy hardware the forks have dropped. Nobody in the thread disputed the release itself; the argument is about pace, not about whether 1.0 is real. With more than 134,000 GitHub stars, the project is one of the most watched open-source AI repositories in the world — and the maintenance question is now attached to a stable API promise.

What to watch#

For anyone building on llama.cpp, the immediate job is migration: audit for removed API calls before upgrading, and expect the stricter versioning to make future breaks easier to plan around. The longer question is whether the stability promise comes with the maintainer capacity to keep it. A 1.0 release is a foundation, not a finish line — and the community's first ask was not for more features, but for more hands.

Frequently asked questions

What is llama.cpp?

A plain C/C++ library for running large language models — and now vision and audio models — locally, on hardware from phones to servers. It powers apps including Ollama and LM Studio, and the Llama desktop apps.

Does upgrading to v1.0 break my app?

It can, if your app uses API calls removed in this release — 35 deprecated functions were pruned. Apps built on the current public API should upgrade cleanly, and from here on breaking changes will be signalled by a major-version bump.

Where do I get v1.0?

Pre-built binaries are on the GitHub releases page, with packages via Homebrew, Winget, conda-forge, MacPorts, and Debian, plus Docker images and the Llama desktop apps at llama.app.
