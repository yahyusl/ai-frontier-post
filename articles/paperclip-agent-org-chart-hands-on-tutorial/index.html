You have 20 Claude Code terminals open and you cannot say which one is doing what. A runaway loop burned through your token budget before lunch, and when the machine reboots every session is gone. Paperclip is the layer above the agents: a self-hosted, open-source Node.js server and React UI that turns your coding agents into an org chart with goals, budgets, and approval gates. The project's own pitch says it best: if OpenClaw is an employee, Paperclip is the company.

Paperclip (paperclipai/paperclip, ~98,000 stars on GitHub, MIT license) picked up over 10,000 stars in the week to October 4, 2026 — the loudest launch week of any agent tooling project this month. It works with the agents you already use: OpenClaw, Claude Code, Codex, Cursor and Cursor Cloud, Gemini CLI, OpenCode, Pi, Hermes, Grok Build, and Kimi Code. The README's hiring rule: if it can receive a heartbeat, it's hired. Here is the full walkthrough, verified against the project's own docs.

What you'll need

  • Node.js 24.11 or newer. Check with node --version — Paperclip requires a newer Node than most LTS setups ship.
  • A model-provider API key. Anthropic, OpenAI, or OpenRouter. Your agents spend real tokens; Paperclip manages them, it doesn't pay for them.
  • About 15 minutes. The install itself is one command.

1. Install with one command

The fastest route works in any terminal:

npx paperclipai@latest onboard --yes

The CLI runs from npm's cache; your instance configuration and data persist locally. The quickstart defaults to trusted local loopback mode. If you use a private npm registry (for example GitHub Packages) via a global ~/.npmrc, npx may resolve paperclipai against it and fail with an E404 — force the public registry for this command:

npx --registry https://registry.npmjs.org paperclipai@latest onboard --yes

To expose the dashboard beyond localhost from the start, pick a bind preset:

npx paperclipai@latest onboard --yes --bind lan
# or:
npx paperclipai@latest onboard --yes --bind tailnet

Already configured? Rerunning onboard keeps your existing config; use npx paperclipai configure to edit settings. The package is published on npm as paperclipai (latest: 2026.1005.0, updated October 6, 2026).

2. Test-drive it with zero commitment

Before you install anything persistent, run an isolated instance that is already initialized with a CEO agent. It stays in the foreground, never installs a service, and opens the browser once setup succeeds:

ANTHROPIC_API_KEY=sk-ant-... npx paperclipai test-drive

Prefer a different harness or model:

OPENAI_API_KEY=... npx paperclipai test-drive --harness codex
OPENROUTER_API_KEY=... npx paperclipai test-drive \
  --harness opencode \
  --model openrouter/anthropic/claude-sonnet-4.5

Each run without --data-dir gets a unique, retained temporary directory — its absolute path is printed at startup. Pass --data-dir to reuse one, or --no-browser to leave the initialized instance unopened. When invoked from a linked Git worktree, test-drive also enables task execution in that worktree.

3. Hire your team: build the org chart

This is the step that makes Paperclip different from a pile of agent tabs. In the dashboard:

  • Define the goal first. The README's example: "Build the #1 AI note-taking app to $1M MRR." Linked tasks and projects carry goal ancestry, so every agent sees the why behind its work, not just a ticket title.
  • Hire the team. CEO, CTO, engineers, designers, marketers — any bot, any provider. Agents get roles, titles, reporting lines, permissions, and their own budgets.
  • Choose harness and model per agent. Your researcher can run on a cheap model via OpenCode while your engineer runs Claude Code on a frontier model. Mixed human-plus-agent org charts are supported.

4. Set budgets and approval gates

This is the feature that pays for the install. Paperclip tracks token and cost spend by company, agent, project, goal, issue, provider, and model, with scoped budget policies:

  • Threshold alerts warn you before spend gets silly.
  • Hard stops pause work at configured limits — enforcement uses recorded spend, so in-flight work can delay a stop slightly.
  • Governance gates add review and approval stages to execution; you can pause, reassign, or terminate any agent's work from the dashboard.

5. Put recurring work on autopilot

Scheduled routines run recurring work on cron, webhook, or API triggers. Each routine execution creates a tracked issue and wakes the assigned agent — no manual kick-offs, and every run keeps its output and history. Customer-support triage, social posts, weekly reports: define them once as routines with an owner.

6. Connect your apps

Wire in GitHub, Notion, and Railway, or your own MCP server through the governed tool gateway. Each connection gets an action policy — Allowed, Ask first, or Off — and you control which agents can use which connections. Managed GitHub operations can even use the GitHub identity of the person directing the work, so commits land under the right name.

What you built

A persistent, ticket-based company for your agents. Tasks carry atomic checkout with execution locks, so two runs never claim the same work. Sessions survive reboots. Every mutation, heartbeat, cost event, and approval lands in a durable activity log you can audit. And because Paperclip is MIT-licensed and self-hosted — single Node.js process with an embedded Postgres locally, or your own Postgres and Docker in production — the company runs on your hardware, not someone else's cloud.

Honest limitations

  • Heartbeat model, not employees at desks. Agents wake for assigned work, follow-up messages, and scheduled heartbeats — they are not continuously running. A mention alone does not assign work or wake another agent.
  • Telemetry is on by default. Paperclip collects anonymous usage telemetry; no prompts, file paths, or secrets are collected, and you can disable it with PAPERCLIP_TELEMETRY_DISABLED=1.
  • You still pay your model provider. Budgets are a guardrail against runaway spend, not a discount.
  • Roadmap gaps. Bring-your-own-ticket-system (Asana / Linear / Jira as on-ramps), the desktop app, and first-party cloud deployments are still on the roadmap — the self-hosted server is the real product today.
  • Docs to bookmark: the five-minute quickstart, the installation reference, and the GitHub repo (2,700+ merged PRs).
