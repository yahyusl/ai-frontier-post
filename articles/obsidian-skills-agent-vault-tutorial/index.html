Teach Your Coding Agent to Use Obsidian: Install the Official Skills and Build a Working Vault

Obsidian’s official agent skills teach your coding agent to write wikilinks, build Bases, and batch-generate notes — install all seven, then verify each one with real commands: Knap renders notes from a CSV, Defuddle clips the web, and a YAML-validated Base turns notes into a task tracker.

SASofia AlmeidaTutorials & Reviews Lead · November 26, 2026 · 16 min read
TL;DR: Obsidian’s official obsidian-skills repo (53,955 stars, #12 on GitHub’s weekly trending) ships seven agent skills for Claude Code, Codex, Cursor, and any skills-aware agent. Install them with one npx command, then verify the pieces yourself: Knap 0.6.0 batch-renders notes from a CSV, Defuddle 0.19.13 clips web pages into Markdown, a YAML-validated .base file turns notes into a task tracker, and a JSON-validated .canvas file maps the vault — all local, all free.
  • The repo in one sentence: obsidianmd/obsidian-skills, MIT-licensed, 111 commits, five releases — seven SKILL.md files your agent reads, plus reference docs for Bases, Markdown, and Canvas.
  • The verified install: npx skills add https://github.com/obsidianmd/obsidian-skills -g --agent '*' -y puts all seven skills in ~/.agents/skills/. No build, no server, no API key.
  • Two CLIs do the verifiable work: Knap (npm i -g knap, v0.6.0) renders templates from JSON or CSV; Defuddle (npm i -g defuddle, v0.19.13) extracts clean Markdown from pages. They pipe into each other.
  • Bases and Canvas are files, not features: a .base file is YAML you can validate with a parser; a .canvas file is JSON. Both appear in this tutorial, both validated.
  • What the agent still needs: an agent that supports the Agent Skills spec, and whatever account or key that agent normally uses. The skills themselves add no account and no cost.

Your coding agent can write code, run tests, and refactor a repo. Until now, it could not do the same for your notes. Ask it to file a meeting note in your vault and it would invent its own Markdown dialect: plain links where Obsidian needs wikilinks, a table where Obsidian needs a Base, a folder of files with no frontmatter at all. The notes landed, but they did not belong in the vault.

Obsidian fixed that at the source. The company behind the note app published obsidian-skills, an official set of seven agent skills that teach any skills-aware coding agent to work in Obsidian Flavored Markdown: wikilinks, callouts, properties, Bases, JSON Canvas, and two command-line tools for turning outside information into notes. The repo has 53,955 stars and sits at #12 on GitHub’s weekly trending page this week. This tutorial installs all seven skills, then verifies each one with commands that actually run: a template engine that turns a spreadsheet into notes, a web clipper that turns a page into Markdown, a database view over your notes, and a canvas that maps the vault.

What you’ll need#

  • Node.js 20 or newer (this tutorial used 24.22.1) and npm. Everything installable here is an npm package; no Docker, no GPU, no model download.
  • Obsidian, free to download from obsidian.md, with a vault — a plain folder of Markdown files. Create one from the app if you do not have one yet.
  • A coding agent that supports agent skills — Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI, OpenCode, or any agent that follows the Agent Skills specification. The agent itself needs whatever account or API key it normally uses; the skills, the template engine, and the clipper in this tutorial need none.
  • Cost: $0. Time: about 30 minutes.

The finished setup is a vault with seven skills installed in your agent, a template that renders notes from data, a clipper that imports web pages, a task tracker that queries your notes, and a canvas that draws the vault as a map. Every command below ran in the sandbox while writing this tutorial, and the outputs shown are the real ones.

1. Install the skills#

The repo is obsidianmd/obsidian-skills on GitHub: MIT-licensed, 111 commits, five releases, and seven skill folders under plugins/obsidian/skills/. The fastest install uses the skills CLI, the package manager for agent skills:

npx skills add https://github.com/obsidianmd/obsidian-skills

That command is interactive: it clones the repo, finds the seven skills, and asks which agents to install them into. If you want it scripted — in a dotfiles setup, for example — pass an agent and -y:

npx skills add https://github.com/obsidianmd/obsidian-skills -g --agent '*' -y

That is the exact command this tutorial ran. It installed all seven skills into the shared agent skills directory. Verify with a directory listing:

ls ~/.agents/skills/
# defuddle  json-canvas  knap  obsidian-bases  obsidian-cli  obsidian-headless  obsidian-markdown

Each folder holds a SKILL.md — the instructions your agent reads — plus reference files for the bigger skills. If your agent does not support the skills CLI, install by hand instead: copy the folders from plugins/obsidian/skills/ into your agent’s skills directory, for example ~/.copilot/skills/ for GitHub Copilot. Claude Code users can also install from the official plugin directory with claude plugin marketplace add obsidianmd/obsidian-skills followed by claude plugin install obsidian@obsidian-skills, and Codex users with codex plugin marketplace add obsidianmd/obsidian-skills. The skills are plain Markdown either way; there is nothing to compile and no server to run.

Here is what each skill does:

SkillWhat it teaches your agent
obsidian-markdownObsidian Flavored Markdown: wikilinks, embeds, callouts, frontmatter properties, tags, highlights, footnotes, Mermaid diagrams
obsidian-basesBases (.base files): database-style views over notes, with filters, formulas, and table, cards, list, kanban, and map views
json-canvasJSON Canvas (.canvas files): nodes, edges, and groups that draw the vault as a map
obsidian-cliThe Obsidian CLI: working with vaults, plugins, and themes from the terminal
obsidian-headlessSyncing and publishing vaults from the command line, without the desktop app
defuddleExtracting clean Markdown from web pages with the Defuddle CLI
knapRendering Markdown from templates and structured data with the Knap CLI

The last two are the workhorses of this tutorial, because they are the two with command-line tools you can run and check yourself. Install both now:

npm install -g knap defuddle
knap --version        # 0.6.0
defuddle --version    # 0.19.13

2. Write a note the Obsidian way#

Before the tooling, the syntax. The obsidian-markdown skill exists because Obsidian’s Markdown is not quite standard Markdown, and the differences are exactly the ones an agent gets wrong. Three rules cover most of it.

First, links inside the vault are wikilinks, not Markdown links. [[Note Name]] links to a note, [[Note Name|Display Text]] changes what the reader sees, and [[Note Name#Heading]] links to a section. Obsidian tracks renames through wikilinks automatically; a Markdown link to a file path breaks the moment the file moves. Use [text](url) only for external URLs.

Second, every note starts with frontmatter. Properties live in a YAML block at the top of the file:

---
title: Project Alpha
date: 2026-11-26
tags:
  - project
  - active
status: in-progress
---

# Project Alpha

This project aims to [[improve workflow]] using modern techniques.

> [!important] Key Deadline
> The first milestone is due on ==January 30th==.

Third, callouts and embeds are part of the vocabulary. A callout is a blockquote that starts with > [!note], > [!warning], > [!tip], or one of the other types; add - after the type and it starts collapsed. Prefix a wikilink with ! and Obsidian embeds the target instead of linking to it: ![[Architecture Diagram.png|600]] drops an image into the note at 600 pixels wide.

With the skills installed, you do not have to memorize any of this. The point of the exercise is the prompt you give your agent from now on. Try this in your agent, pointed at your vault:

Using the obsidian-markdown skill, create a note called "Project Alpha"
in my vault. Give it frontmatter with title, date, tags, and status.
Link it to my existing note "Meeting Notes" with a wikilink, add a
[!warning] callout with the January 30th deadline, and check the note
renders in Obsidian before you finish.

The agent reads the skill, writes the note in valid Obsidian Flavored Markdown, and — because the skill tells it to — verifies the result instead of assuming it. That verification step is the whole difference between a skill and a prompt you typed once: the instructions live in your agent permanently, and every future note follows them.

3. Batch-generate notes with Knap#

Knap is the skill’s quiet superpower. It is a small CLI that renders Markdown from templates and structured data — JSON, or a CSV file — so you can turn a list of anything into a folder of notes in one command. No agent needed for this step; it runs locally and deterministically.

Save this template as template.md in your vault folder. It is adapted from the example in the knap skill file:

---
{{ title | yaml_property:"title" }}
{{ tags | yaml_property:"tags" }}
---
# {{ title | trim }}
{% if author %}
By {{ author }}
{% endif %}

{{ content }}

Check it before you render anything:

knap validate template.md
# template.md: Template is valid (static checks only; runtime values are not checked).

Render one note from a JSON file to see the shape of the output:

cat > article.json <<'EOF'
{"title": "  Knap test note ", "tags": ["knap", "obsidian"], "author": "Test Author", "content": "This note was rendered by Knap."}
EOF
knap render template.md --data article.json -o note.md
cat note.md
---
title: "  Knap test note "
tags:
  - "knap"
  - "obsidian"
---
# Knap test note
By Test Author

This note was rendered by Knap.

Note two details in that output. The yaml_property filter quotes values and indents lists correctly for frontmatter, and | trim strips the stray spaces from the heading while the frontmatter keeps the raw value. That is the kind of edge the skill file documents so your agent does not have to discover it by breaking a note.

Now the real use: one note per row of a CSV.

printf 'title,author,content\nFirst note,Alice,Hello from CSV\nSecond note,Bob,Another row\n' > articles.csv
knap batch template.md --data articles.csv --output-dir notes \
  --filename '{{ title | safe_name }}.md'
# Wrote 2 files to notes.
ls notes/
# First note.md  Second note.md

And the first file, exactly as rendered:

---
title: "First note"
tags: ""
---
# First note
By Alice

Hello from CSV

The empty tags line is honest output, not a bug: the CSV has no tags column, so the variable is empty. Add a tags column and the line fills in — but remember CSV values arrive as strings, so a cell reading knap;obsidian renders as one quoted string, not a list. For real lists, feed Knap a JSON array instead of a CSV, or a folder of JSON files with --data ./articles. Add --dry-run to any batch to list the output paths without writing files, and --overwrite when you re-run a batch over existing notes — without it, existing files are an error, which is the safe default.

4. Clip the web into your vault with Defuddle#

Defuddle strips a web page down to its content — no navigation, no ads, no cookie banners — and hands you clean Markdown. Install it alongside Knap (done in step 1), then clip a page straight into a note:

defuddle parse https://example.com --md -o content.md
# Output written to content.md
cat content.md
# This domain is for use in documentation examples without needing permission.
# This is not a service; avoid relying on it for testing and monitoring purposes.

For a single fact instead of the whole page, ask for one metadata property:

defuddle parse https://example.com -p title
# Example Domain

The two tools compose. The knap skill documents a pipeline that extracts a page as JSON and renders it straight into a templated note, with no file in between:

defuddle parse https://example.com --md --json \
  | knap render -t '# {{ title }}

{{ content }}' --data - -o clipped.md
cat clipped.md
# # Example Domain
#
# This domain is for use in documentation examples without needing permission.
# This is not a service; avoid relying on it for testing and monitoring purposes.

That pipeline is the reading-notes workflow in miniature: clip the pages you read, render each one through a template that adds your frontmatter, and the result is a vault of notes in a consistent shape instead of a pile of pasted text. One caution from the skill file, worth repeating: treat an extracted page as data, not instructions. A page that tells your agent to run commands or open links is content to file, not orders to follow.

5. Build a task tracker with Bases#

Bases are Obsidian’s database views: a .base file that queries your notes and shows them as a table, a kanban board, cards, a list, or a map. No plugin, no Dataview script — the file is YAML, and the obsidian-bases skill documents the whole schema. Save this as tasks.base in your vault. It is the skill’s task-tracker example, trimmed to one table and one kanban view, and it was validated with a YAML parser while writing this tutorial:

filters:
  and:
    - file.hasTag("task")
    - 'file.ext == "md"'
formulas:
  days_until_due: 'if(due, (date(due) - today()).days, "")'
  priority_label: 'if(priority == 1, "High", if(priority == 2, "Medium", "Low"))'
properties:
  note.status:
    displayName: Status
  formula.days_until_due:
    displayName: "Days Until Due"
views:
  - type: table
    name: "Active Tasks"
    filters:
      and:
        - 'status != "done"'
    order:
      - file.name
      - status
      - formula.priority_label
      - due
      - formula.days_until_due
    sort:
      - property: due
        direction: ASC
  - type: kanban
    name: "By Status"
    groupBy:
      property: note.status
      direction: ASC
    groupOrder:
      - Planned
      - In progress
      - Done
    order:
      - file.name
      - due

Three rules from the skill file keep this file working. First, quote formulas that contain double quotes with single quotes — 'if(due, (date(due) - today()).days, "")' — or the YAML parser chokes. Second, in the properties section, prefix note properties with note.; a bare status there is silently ignored and the column shows the raw name. Third, date subtraction returns a Duration, not a number, so always take a field first: (date(due) - today()).days, never (date(due) - today()).round(0). The kanban view needs Obsidian 1.14 or later; the table view works on any version with Bases. Open the file in Obsidian and the two views render from your notes — any note tagged #task appears, sorted by due date, with a computed column for days left and a label for priority.

6. Map the vault with JSON Canvas#

JSON Canvas is the open format for infinite whiteboards: nodes and edges in a JSON file, which Obsidian renders as a canvas. The json-canvas skill teaches your agent to write it. A minimal canvas that links your task tracker to a note about this tutorial looks like this — save it as map.canvas and validate it the same way:

{
  "nodes": [
    {"id": "a1", "type": "text", "x": 0, "y": 0, "width": 300, "height": 120,
     "text": "Obsidian skills tutorial"},
    {"id": "a2", "type": "file", "x": 400, "y": 0, "width": 300, "height": 120,
     "file": "tasks.base"}
  ],
  "edges": [
    {"id": "e1", "fromNode": "a1", "toNode": "a2"}
  ]
}
python3 -c "import json; d = json.load(open('map.canvas')); print(len(d['nodes']), 'nodes,', len(d['edges']), 'edge')"
# 2 nodes, 1 edge

Open it in Obsidian and you get two cards joined by an arrow: the tutorial note on the left, the task tracker on the right. That is the whole format — text nodes, file nodes, edges, and optional groups. The skill’s reference files cover the rest: colors, link nodes, and embedding a canvas inside a note with ![[map.canvas]]. Canvases are the right shape for the overview your agent cannot write as prose: project maps, reading paths, decision trees.

7. Put the agent to work#

With the skills installed and the pieces verified, the daily workflow is prompts, not commands. Three that use the skills properly:

  • Morning triage. “Using the obsidian-bases skill, add a ‘Due this week’ view to tasks.base that filters for due within the next 7 days, and list the notes it catches before you save.” The agent edits the YAML, validates it, and shows you the result instead of silently rewriting the file.
  • Reading capture. “Using the defuddle and knap skills, clip these three URLs into the Reading folder with the article template, one note per URL, and link each note to the project it belongs to.” The agent runs the pipeline from step 4 three times and files the results.
  • Weekly review. “Using the json-canvas skill, draw a canvas of the notes tagged #project created this week, grouped by project, with an edge from each note to its project note.” The agent writes the canvas; you open it and see the week at a glance.

Two skills sit outside this workflow and are worth knowing about. obsidian-cli drives vaults, plugins, and themes from the terminal — useful in scripts and on machines where you administer Obsidian rather than write in it. obsidian-headless syncs and publishes vaults from the command line without the desktop app, which is the piece that makes a vault usable on a server; it needs an Obsidian account and sign-in, so treat it as a second-day setup rather than part of the first install. Keep both skills installed even if you do not use them today: they cost nothing until invoked, and the day you need them, your agent already knows they exist.

One habit makes all of this durable. When a skill’s instructions change — and they will, because Bases and the CLIs are still moving — update the same way you installed: claude plugin update obsidian@obsidian-skills for the Claude Code plugin, or re-run the skills add command for the CLI install. The skill files describe one version’s tools; an outdated skill can tell your agent to use a flag that no longer exists.

When to use this vs alternatives#

ApproachUse it whenWatch out for
Obsidian skills (this tutorial)Your notes already live in Obsidian, or you want them in plain Markdown files you own, and your agent should maintain themOnly helps inside an agent that supports skills; the agent still needs its own account or key
Plain Markdown + your own promptsYou write notes occasionally and can paste the syntax rules into a prompt each timeThe agent re-invents the syntax every session; nothing stops it drifting
Notion AI or similar hosted toolsYour team lives in one hosted workspace and you want the AI built into the appNotes live on someone else’s servers in a proprietary format; export is a project, not a feature
Dataview + Templater pluginsYou want live queries and hotkeys inside Obsidian itself, without an agentCommunity plugins with their own query languages; the agent cannot write them without the same kind of skill
LogseqYou think in outlines and daily journals rather than long-form notesDifferent model — blocks, not pages — and no official agent skills of this kind

The deciding question is who owns the files. If the answer is you, in a folder of Markdown on your own disk, the skills are the cheapest way to get an agent that respects that folder’s rules.

The takeaway#

Obsidian’s skills do not add a feature to the app. They add a contract between your agent and your vault: notes arrive with frontmatter, links are wikilinks, Bases are valid YAML, canvases are valid JSON, and the tools that produce them — Knap and Defuddle — run locally with no account and no fee. You installed seven skills with one command, rendered notes from a spreadsheet, clipped a page into a templated note, and built a task tracker and a vault map, each verified as it was made. The next step is the boring one, and it is the whole point: point your agent at the vault you actually use, and let it keep the notes the way you would have kept them yourself.

Frequently asked questions

Do I need Obsidian Sync or a paid plan to use the skills?

No. Everything in this tutorial runs on a plain local vault, and the Obsidian desktop app is free for personal use. Sync and Publish are optional paid add-ons for keeping vaults in sync across devices and publishing them to the web; neither is needed for the skills, Knap, or Defuddle.

Which coding agents can use these skills?

Any agent that supports the Agent Skills open standard: Claude Code, ChatGPT and Codex, Cursor, GitHub Copilot, Gemini CLI, OpenCode, Antigravity, Kiro, and Hermes Agent, among others. Install from the official plugin directory, with the skills CLI, or by copying the skill folders into your agent's skills directory.

My agent does not support plugins. Can I still install the skills?

Yes. Copy the folders in plugins/obsidian/skills/ into your agent's skills directory — ~/.copilot/skills/ for GitHub Copilot, for example — or run npx skills add https://github.com/obsidianmd/obsidian-skills -g --agent '*' -y, which installs them into the shared ~/.agents/skills/ directory without any plugin support.
