NeonClipping hands-on: turn long streams into captioned vertical Shorts, free and local

NeonClipping went from zero to 2,800 stars in eight days by doing one job locally: turning long YouTube, Twitch, and Kick videos into captioned 9:16 clips with no account, no upload, and no subscription. Here is the install and the first run — verified end to end on a 2-core machine with no GPU — and where it falls short.

PNPriya NairResearch Editor · November 27, 2026 · 13 min read
TL;DR: NeonClipping turns long YouTube, Twitch, and Kick videos into captioned 9:16 Shorts on your own machine — no account, no upload, no subscription. Install is one script plus Python and FFmpeg; the first local run downloads a 142 MB speech model and, in this sandbox, produced two 1080×1920 clips with real burned-in captions in 156 seconds on a 2-core CPU with no GPU. Add Ollama for AI-written titles and hooks; without it, titles stay generic.
  • Why it is blowing up: created 19 November 2026 by Ajay K Meena; 2,814 stars, 179 forks, and 89 commits eight days later (27 November 2026).
  • What it does: Fast mode downloads audio only, uses YouTube’s own word-timed captions, scores moments by loudness jumps and raised voices, then downloads only the chosen sections and renders 1080×1920 clips with burned-in captions.
  • Verified here: 83-second local MP4 → 2 clips, 28.0 s each, 1080×1920 H.264/AAC, 74 and 81 caption words, in 156 s on 2 CPU cores with no GPU and no Ollama.
  • Without a local LLM: moment scores come from audio and motion only, and titles are generic (“Activity highlight 1”). Ollama with llama3.2:3b adds AI titles, hooks, and scores.
  • License: AGPL-3.0 since 24 November 2026 (MIT before). If you run a changed version as a service for others, you must publish the source.

Eight days after its first commit, NeonClipping had 2,814 stars on GitHub. That is not normal for a weekend project. The reason is simple: it does one job, locally, that creators currently pay a subscription for. Paste a YouTube, Twitch, or Kick link — or drop in your own MP4 — and it returns captioned 9:16 clips with a title and a hook. No account, no upload, no credits. The whole thing is a Python FastAPI server that runs on your own machine.

The project is the work of Ajay K Meena, a director, director of photography, and DaVinci Resolve educator from Jaipur. It is open source under AGPL-3.0 (versions before 24 November 2026 stay MIT). This tutorial installs it, runs it, and makes real clips — verified end to end on a 2-core virtual machine with no GPU. Every command below ran in that sandbox unless it is explicitly marked as quoted from the project's documentation.

1. What you'll need#

The requirements are short, and they are the whole list:

  • Python 3.10 to 3.13. The README warns that the newest Python often has no wheels for the speech and vision packages yet. Python 3.12 is the safe pick; the sandbox used 3.12.3.
  • FFmpeg on your PATH. Check with ffmpeg -version. The build matters: burned-in captions need the ass filter (libass). The sandbox used FFmpeg 8.1.2, which has it. One hands-on report from a Mac found Homebrew's FFmpeg could not burn subtitles — if captions render as plain text or not at all, your FFmpeg build is the first suspect.
  • About 150 MB of downloads on first use, plus the repo itself. The first local-file run downloads the faster-whisper base speech model (142 MB in this run) for transcription. YouTube links skip that step because they use YouTube's own captions.
  • 2 GB of free space on the drive holding the app's data. The server refuses new Make jobs with a 'disk is almost full' error when the data drive drops under 2 GB free. Keep the source files and clips somewhere with room.
  • Optional: Ollama with llama3.2:3b. Without it, clips are picked by the audio and motion score and titles are generic. With it, a local model scores each moment and writes the title and hook. A GPU helps (NVENC export, faster transcription) but is not required — everything below ran on CPU.

2. Install it#

On Windows, the one-click path is NeonClipping-Setup.bat from the Releases page: it checks the machine, installs Python and FFmpeg if missing, and opens the app. On Mac and Linux, clone the repo and run the launcher:

git clone https://github.com/iamajmeena/neonclipping
cd neonclipping
./run.sh

The launcher creates a .venv on first run, installs requirements.txt, and starts the server. In the sandbox the install took about two minutes and pulled in FastAPI 0.165, faster-whisper 1.2.1, yt-dlp 2026.11.23, OpenCV, and the rest — no errors, no missing wheels on Python 3.12. When it is up you will see Uvicorn's startup lines, and the app lives at http://127.0.0.1:8770. The server binds to localhost only by default; nothing leaves your machine unless you ask it to.

Two environment variables are worth knowing before the first run. NEONCLIPPING_CPU=1 forces CPU for speech recognition and encoding — set it on any machine without an NVIDIA GPU. NEONCLIPPING_NO_AUTOUPDATE=1 turns off the daily yt-dlp self-upgrade the app otherwise performs at startup. Auto-update of the app itself is on by default: a green banner offers the new version, and it applies automatically after a short countdown when nothing is running, keeping one backup in .update-backup/. A git checkout is never touched by the updater.

3. Make your first clips#

Open http://127.0.0.1:8770, paste a link, press Make clips. That is the intended flow, and it is worth saying plainly what happened when I tried it here: it did not work from this sandbox. The first attempt failed on a certificate error from the sandbox's network proxy; a direct yt-dlp check then failed with YouTube's own 'Sign in to confirm you're not a bot' challenge. Both failures are the exact ones the README documents, with the exact fixes: upload the MP4 instead ('always works'), pass your browser login with NEONCLIPPING_COOKIES_BROWSER=chrome, or drop a cookies.txt export into data/youtube_cookies.txt. Datacenter IPs get challenged; a home connection usually does not. The local-upload path below is the one I ran end to end, and it is the path that cannot be blocked.

For the test I generated an 83-second 1280×720 MP4 with ffmpeg — a test pattern with a synthetic spoken commentary track, including one deliberately louder stretch so the moment detector had something to find. Upload it with the Upload video button next to the link box, then set:

  • Mode: Fast (the default for videos over 10 minutes; for a short file it runs the same local pipeline)
  • Clips: 2
  • Min / Max length: 15 / 40 seconds
  • Layout: Blurred fill
  • Caption style: GTA Neon
  • Language: English

Press Make clips and watch the progress line. On this 2-core CPU machine the job took 156 seconds from click to 'Clips ready': scanning movement and audio, transcribing the speech with the local model, reading two candidate moments, checking action in the best moments, then exporting each clip. Your time will vary with CPU and clip count; the README's own measured numbers, on an RTX 2060 with 16 threads, are 97 seconds for three clips from an 85-minute YouTube stream and 14 seconds for a 90-second local MP4. Treat those as the GPU case, not the promise for a laptop.

4. Read the results#

The job returned two clips, both exactly 1080×1920, H.264 video with AAC audio, 28.0 seconds each, about 10 MB apiece. The first covers 30.8–58.8 seconds of the source — the loud stretch sits inside it — and the second covers 0–28 seconds. Each clip carries a score breakdown: clip one scored 34 overall (energy 24, action 28, words 26); clip two scored 22. The reason field is honest about what drove the pick: 'Cues: fast motion'.

The captions are real. Clip two's SRT file opens with 'Welcome back to the channel. Today we are breaking down the final 10 minutes of last night's ranked…' — a correct transcription of the synthetic speech, word-timed across 81 caption words. Clip one has 74. The burned-in captions render in the GTA Neon style — uppercase, cyan-to-pink, thick outline — exactly as the style promises. A frame pulled from each clip confirms the layout too: the 'blurred fill' layout keeps the full landscape frame with a blurred copy filling the vertical space above and below.

Two things will look wrong if you expect a finished product, and both are by design. The titles are generic — 'Activity highlight 1' and 'Activity highlight 2' — and the hooks are empty, because no language model was configured; the ai score axis reads null in the job result. And the facecam finder correctly reported 'no facecam' for a test pattern with no face in it. Both are the app telling the truth about what it had to work with. Verify your own output the same way I did:

ffprobe -v error -show_entries stream=codec_type,codec_name,width,height \
  -show_entries format=duration -of default=noprint_wrappers=1 clip.mp4

You should see 1080×1920, h264, aac, and a duration inside your min/max range. The clip files, their SRT/ASS/VTT caption files, and a JSON record of settings and word timings all live under the app's data/ folder, next to the uploaded source.

5. Tune the clips#

The first render is a draft. The editor is where the tool earns its keep:

  • Layouts (11). Camera above or below the gameplay, blurred fill, full-screen crop, gameplay only, four corner facecam overlays, circle facecam, and side-by-side. The Find my facecam chip scans 14 frames for a rectangle with a steady border that holds a face (a small local YuNet model, shipped in the repo's models/ folder) and answers 'no facecam' when it is not sure. If you pick the wrong corner, the clip shows the wrong area — the presets are starting points, so draw your own boxes when the cam is not where the preset assumes.
  • Caption styles (5). GTA Neon, Impact, Clean, Hormozi, and MrBeast, plus editable words, caption height, and six animations (highlight, pop-in, pop-in line, one by one, build up, full line). You can import an SRT, ASS, or WebVTT file and retime words by hand.
  • Length and mix. Min/max clip length snaps ends to sentence boundaries. The moment mix — Balanced, Action, or Dialogue — shifts the ranking toward energy, story, or a blend, and the star ratings you give finished clips feed a small on-device ranker that adjusts the weights after eight rated moments.
  • Re-editing is cheap. Changing a layout or a caption style re-exports only the final MP4; the source, the moments, and the transcript are reused, not recomputed. The project's own validation re-exported seven clips across all 11 layouts and five styles in about two minutes.

6. Add a local LLM for real titles#

This step is quoted from the project's README — I ran the no-LLM path in the sandbox, so treat the commands as the documented setup, not as commands I executed here. Install Ollama, then pull the model the README recommends:

ollama pull llama3.2:3b

With Ollama running, NeonClipping sends each candidate moment's transcript to the local model, which scores the moment and writes the title and hook. The 'Balanced' and 'Dialogue' mixes prefer a locally installed Gemma 4 judge when one is present; other local models stay as fallback. The model sees text only — it cannot see the screen — and the transcript text is the only thing that leaves the app, to a model on your own machine.

If your machine is too slow for a local model, the same scoring can use a cloud provider instead: open Cloud AI (optional) in the app, pick Groq, OpenRouter, Gemini, OpenAI, or LM Studio, paste a key, and tick Use Cloud AI. The key is stored in data/llm.json on your computer. Speech-to-text still uses YouTube's captions or the local model either way.

7. Live clipping and creator watch#

Two features go beyond cutting finished videos, and both are documented here from the README and the source — I did not run them live, because they need a stream that is live right now. Live clipping takes a Twitch channel or YouTube Live link, records the stream, reads chat anonymously, and cuts a clip around every chat spike (velocity above 2.5 sigma and 2.5× the five-minute baseline), starting about 24 seconds before the spike, since chat reacts after the moment. A phone remote (start with NEONCLIPPING_LAN=1) shows a Wi-Fi address and a six-digit PIN, a hype meter, and a Clip now button. Creators watches a Twitch or YouTube channel, checks every minute, and starts recording and clipping automatically when that creator goes live. Unattended sessions stop after three hours or when less than 8 GB of disk is free; one stream records at a time. The project reports live clipping tested end to end on Twitch; a YouTube auto-clip was not run end to end by the maintainer.

When to use this vs the alternatives#

Short-form clipping is crowded. The choice is about where the work happens and who the tool is for:

ToolWhere it runsCostBest for
NeonClippingYour PC, local serverFree, no accountStreamers and gamers: facecam layouts, live clipping, Twitch/Kick, no Docker
OpusClipTheir cloudSubscription / creditsTeams that want zero setup and do not mind uploading footage
AutoClipYour PC, desktop app / CLI / MCPFree, open sourcePodcasts and interviews; Docker option; agent-driven workflows
Docker self-hosted clippers (SupoClip, OpenShorts, Reelsaw)Your machine or serverFree, Docker setupSelf-hosters comfortable running containers

Pick NeonClipping when the source is a stream or gameplay, when the facecam matters, or when you want live clipping while the stream is still on. Pick AutoClip when the source is a podcast or an interview and you want a desktop app or an MCP server your coding agent can drive. Pick OpusClip when you would rather pay than install anything. The README's own comparison table makes the same point: NeonClipping's edge is audio-first downloads (79 MB of audio for an 85-minute video instead of the whole file) and never uploading anything.

Honest limits#

The README has a section with this exact title, and it is worth repeating rather than softening:

  • Highlight picking is a heuristic plus a small local LLM. It finds loud, energetic, quotable moments, not guaranteed viral ones. Review before posting.
  • The action cues are simple heuristics on a tiny low-resolution copy. They rank moments; they do not recognise a police chase or a clutch play.
  • Without YouTube captions, a speech model must transcribe each candidate, which is slow on CPU. Budget accordingly on a laptop.
  • Deep mode was verified on a short video only. On multi-hour videos it downloads the whole file first and is slow by design.
  • Live clipping is one session at a time, and the computer must stay awake and online while it records.
  • Caption accuracy follows the source. YouTube's auto captions are imperfect, especially Hinglish; local transcription is rougher still on noisy game audio.
  • Downloading streams can violate YouTube's or Twitch's terms depending on how you use the output, and the tool does not grant rights to re-upload someone else's gameplay. Use your own footage, or content you have the rights to.
  • The license changed on 24 November 2026 from MIT to AGPL-3.0. You can use, study, change, and share it — but if you share a changed version, or run it for others as a website or service, you must publish your full source under AGPL-3.0 too.

Two more behaviours are worth knowing before you install. The app checks GitHub for new versions — a green banner offers the update, and it applies automatically after a short countdown when nothing is running. And one independent hands-on test on a Mac, published in November, found that while the page is open the app also fetches the latest uploads of 14 YouTube gaming channels every five minutes, for its YouTube tab. That behaviour is not in the README's privacy notes; it is a small, visible network call from an otherwise local tool. The YouTube tab is not required for the core job — upload a file and make clips without it. And the in-app YouTube fetch can be blocked by YouTube's bot check on some networks, which is when the upload-the-MP4 fallback earns its keep.

The takeaway#

NeonClipping is eight days old, has 2,814 stars, and already does the unglamorous parts right: the install is one script, the first run needs no account and no key, the local model downloads itself, and the clips it produced on a 2-core machine with no GPU were correctly framed, correctly captioned, and correctly timed. The rough edges are all visible up front — generic titles without a local LLM, a young project that changes several times a day, and a YouTube fetch that can be blocked — and the README documents every one of them. If you stream or record gameplay and you are tired of paying a subscription to cut your own footage into Shorts, this is the free, local tool to try first. Install it, upload one of your own videos, and judge it by the clips it gives you back.

Frequently asked questions

Do I need a GPU or an Ollama model to use NeonClipping?

No. Everything in this tutorial ran on a 2-core virtual machine with no GPU: the server starts, the faster-whisper base model downloads itself for transcription, and clips render with the CPU x264 encoder. Ollama is optional — it only adds AI-written titles, hooks, and moment scores. Without it, clips are picked by the audio and motion score and titles are generic.

Why does YouTube say “sign in to confirm you’re not a bot”?

YouTube challenges some networks — shared, mobile-data, VPN, or datacenter connections — before it lets yt-dlp download anything. The README documents the fixes in order: upload the MP4 instead, pass your browser login with NEONCLIPPING_COOKIES_BROWSER=chrome, use a cookies.txt export, or switch networks. The local-upload path cannot be blocked and is the one verified end to end here.

What does the AGPL-3.0 license mean for me?

You can use, study, change, and share NeonClipping freely. The AGPL-3.0 obligation bites only if you share a changed version or run it for others as a website or service — then you must publish your full source code under AGPL-3.0 too. Versions released before 24 November 2026 stay under MIT.
