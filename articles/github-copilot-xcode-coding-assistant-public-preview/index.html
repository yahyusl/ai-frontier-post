GitHub Copilot comes to Xcode's built-in coding assistant in public preview

GitHub said on November 4, 2026, that Copilot now works directly inside Xcode's built-in coding assistant, in public preview starting with the Xcode 27.3 beta. It is the first time Copilot sits inside Apple's own assistant instead of arriving through a separate extension — and for Apple developers, it removes one more reason to leave Xcode's native workflow to get AI help with their code.

MDMarcus DoyleSenior Technology Writer · November 4, 2026 · 5 min read
TL;DR: GitHub said on November 4, 2026, that Copilot now works directly in Xcode's built-in coding assistant, in public preview starting with Xcode 27.3 beta. It needs a Mac running macOS Tahoe 26.6 or later, supports all Copilot plans, and does not replace the existing GitHub Copilot for Xcode extension, which remains a separate option.

  • Status: public preview, available starting with the Xcode 27.3 beta.

  • Release-notes detail: Dataconomy reports Apple’s release notes list GitHub Copilot as available in Coding Intelligence under identifier 185837709.
  • Beta context: the Xcode 27.3 beta includes Swift 6.4 and SDKs for the 27.3 platforms; Dataconomy reports the stable release is expected in December alongside macOS 27.3.

GitHub announced the change in a changelog post published on November 4, 2026: “You can now work with GitHub Copilot directly in Xcode’s built-in coding assistant, bringing Copilot into your native Xcode workflow.” The integration is in public preview, available starting with the Xcode 27.3 beta. Until now, the usual route to Copilot in Xcode was the separate GitHub Copilot for Xcode extension, maintained as an open-source project outside Apple’s own tools; the new option plugs Copilot into the assistant Apple builds into Xcode itself.

GitHub presents the native route as an addition, not a replacement. “This gives you another way to use Copilot in Xcode,” the changelog post says, adding that the existing extension “remains a separate option, so you can choose the workflow that works best for you.” In practice, that choice matters: developers who already rely on the extension do not have to move, while developers who prefer Apple’s built-in assistant can now use Copilot there without installing and maintaining a separate add-on.

How to turn it on

Getting started has three requirements, all stated in GitHub’s post. Download the Xcode 27.3 beta from Apple Developer Downloads, run it on a Mac with macOS Tahoe 26.6 or later, and open Xcode > Settings > Intelligence to set up GitHub Copilot in the coding assistant. GitHub says all Copilot plans are supported. Feedback goes in two places: the GitHub Copilot for Xcode repository, or Apple’s Feedback Assistant. Dataconomy reports that Apple’s release notes list GitHub Copilot as available in Coding Intelligence under identifier 185837709.

Where Copilot sits in Xcode’s AI lineup

Copilot joins a built-in roster that has grown steadily, rather than arriving as Xcode’s first AI assistant. According to Dataconomy’s account of the beta, Xcode 26 introduced ChatGPT integration and later added Claude; Xcode 26.3 expanded those integrations with agentic coding capabilities through Codex and Claude Agent; and Xcode 27 added Gemini support, alongside a redesigned interface and multi-turn conversations. Copilot is the next name on that list — and the first Microsoft-owned coding assistant to sit inside Apple’s own assistant. GitHub has meanwhile been pushing Copilot beyond autocomplete: Copilot Fusion and Agentic Workflows went generally available at GitHub Universe, taking model selection off developers’ plates and turning repository chores into scheduled jobs.

The 27.3 beta carries more than the Copilot integration. Dataconomy reports it includes Swift 6.4 and software development kits for iOS 27.3, iPadOS 27.3, tvOS 27.3, watchOS 27.3, macOS 27.3 and visionOS 27.3, and that Xcode 27.3 is expected to be released in December alongside macOS 27.3 and related operating system updates. Those are beta contents and an expected date, not Copilot-specific promises — but they set the timetable developers should expect before the integration reaches a stable Xcode release.

What is still preview — and what to watch

Two labels in GitHub’s announcement deserve attention. The integration is a public preview, and its host is a beta: behaviour may change before a stable release, and developers running production work should not treat it as settled. GitHub’s short changelog post also gives no feature-by-feature comparison with the existing extension, and it does not list which Copilot capabilities appear inside the native assistant beyond working “directly” in it. Until GitHub or Apple documents that in detail, the safe assumption is that the two routes may differ, and developers should test the workflow they depend on rather than assume parity. Copilot’s model roster has also kept changing, with four models retired in October, so what Copilot can do inside Xcode will keep moving even after the integration itself stabilises.

The requirements are the other gate. A developer needs both the Xcode 27.3 beta and macOS Tahoe 26.6 or later, which limits immediate adoption to those willing to run beta software on both fronts. What to watch now is the stable Xcode 27.3 release, any documented comparison between the native integration and the extension, and whether feedback during the preview changes what the built-in assistant can do. For now, the news is narrow and concrete: Copilot is inside Xcode’s own assistant, in preview, for developers on the beta — and the extension is still there for everyone else.

Frequently asked questions

How do I turn on GitHub Copilot in Xcode’s built-in coding assistant?

Download the Xcode 27.3 beta from Apple Developer Downloads, run it on a Mac with macOS Tahoe 26.6 or later, and open Xcode > Settings > Intelligence to set up GitHub Copilot in the coding assistant. All Copilot plans are supported.

Does the new integration replace the GitHub Copilot for Xcode extension?

No. GitHub says the existing GitHub Copilot for Xcode extension remains a separate option, so developers can choose the workflow that works best for them.

Is the Xcode integration finished?

No. It is in public preview and runs on the Xcode 27.3 beta, so behaviour may change before a stable release. GitHub asks for feedback through the GitHub Copilot for Xcode repository or Apple’s Feedback Assistant.
